# 구성 요소 정리 + Superset 대시보드/차트 만드는 법

`02`(아키텍처.md), `03`(파이프라인_설계.md)과 달리 04는 "코드를 설계"하는 게 아니라 **기존 도구들을 조합**하는 작업이라, 대신 (1) 지금 뭐가 떠서 뭘 하고 있는지 컴포넌트별 역할과 (2) Superset에서 실제로 대시보드를 만드는 절차를 정리한다.

---

## 1장. 지금 떠 있는 컴포넌트 목록과 역할

```
MinIO (Gold parquet 파일)
   ↑ 조회
Hive Metastore  ──"이 S3 경로가 이런 스키마의 테이블"──▶  Trino
   (카탈로그/메타데이터 저장)                              (실제 SQL 실행 엔진)
                                                              ↑ SQL 쿼리
                                                          Superset
                                                       (BI 대시보드/차트)
```

| 컴포넌트 | 역할 | 이 저장소에서의 위치 |
|---|---|---|
| **MinIO** | Gold 레이어 parquet 파일이 실제로 저장된 곳(S3 호환 오브젝트 스토리지) | 02가 띄움, `test-bucket/gold/*` |
| **Hive Metastore** | "`s3a://test-bucket/gold/event_funnel`이 `event_type VARCHAR, count BIGINT` 컬럼을 가진 테이블이다"라는 메타데이터(카탈로그)를 저장. 데이터 자체는 안 갖고 있고 "위치 + 스키마" 정보만 관리 | `04/docker-compose.yml`의 `hive-metastore`, 내장 Derby DB 사용 |
| **Trino** | Hive Metastore에 스키마를 물어보고, 실제 데이터는 MinIO에서 직접 읽어와 SQL을 실행하는 쿼리 엔진(MPP) | `04/docker-compose.yml`의 `trino`, 카탈로그 이름은 `minio_lake` |
| **Superset** | Trino에 SQL을 날려서 결과를 차트/대시보드로 시각화하는 BI 웹앱 | `04/docker-compose.yml`의 `superset`, `localhost:8889` |

**핵심 포인트**: 이 넷은 각자 다른 일을 하는 독립 컴포넌트이고, 데이터는 항상 **MinIO에만** 있다. Hive Metastore도, Trino도, Superset도 데이터 사본을 안 갖고 있음 — 그래서 Gold가 재실행으로 갱신돼도(스키마만 안 바뀌면) 아무것도 다시 등록할 필요 없이 다음 쿼리부터 바로 새 데이터가 보임.

## 2장. Superset에서 대시보드 만드는 전체 흐름

Superset의 구조는 **Database 연결 → Dataset → Chart → Dashboard** 4단계로 되어 있다. 각 단계가 다음 단계의 재료가 되는 구조.

```
Database 연결        (이미 등록됨: "Trino (MinIO Gold)")
   ↓
Dataset             (테이블 하나 = 데이터셋 하나, 또는 SQL 쿼리 결과를 데이터셋으로)
   ↓
Chart               (데이터셋 하나 + 어떤 컬럼을 축/지표로 쓸지 + 차트 종류)
   ↓
Dashboard           (차트 여러 개를 한 화면에 배치, 필터 공유 가능)
```

### 2-1. Dataset 만들기

두 가지 방법이 있음:

1. **SQL Lab에서 시작** (탐색하면서 만들 때 추천): 왼쪽 메뉴 `SQL Lab` → `Trino (MinIO Gold)` 데이터베이스 + `gold` 스키마 선택 → 테이블 목록에서 원하는 테이블 클릭하거나 직접 `SELECT ...` 작성 → 실행 후 결과 아래 `Save` → `Save as Dataset`. 여러 테이블을 JOIN한 쿼리도 그대로 데이터셋으로 저장 가능.
2. **Datasets 메뉴에서 바로 만들기**: 왼쪽 메뉴 `Datasets` → `+ Dataset` → Database/Schema/Table을 드롭다운으로 선택. 테이블 하나를 그대로 쓸 때 더 빠름.

### 2-2. Chart 만들기

1. 만들어둔 Dataset을 열거나, `Charts` → `+ Chart`에서 Dataset 선택.
2. **Visualization Type**(차트 종류) 선택 — 여기서 `04/이론.md`의 "데이터 타입별 차트 선택" 기준을 참고.
3. **Metrics**(지표, 보통 숫자 컬럼을 SUM/COUNT/AVG 등으로 집계)와 **Dimensions/Group by**(범주형 컬럼, 막대/선을 나누는 기준)를 지정.
4. 우측 상단 `Run` → 미리보기 확인 → `Save`(어느 Dashboard에 넣을지 이 시점에 바로 선택 가능).

실제로 만들어본 예시(`brand_revenue` 테이블, Bar 차트): Metric = `SUM(revenue)`, X축 = `brand` — 브랜드별 매출 합계를 막대로 비교하는 가장 기본적인 패턴.

### 2-3. Dashboard 만들기

1. `Dashboards` → `+ Dashboard`.
2. 우측 패널에서 기존에 만든 Chart들을 드래그해서 캔버스에 배치, 크기 조절.
3. 여러 차트가 같은 컬럼(예: `category_code`)을 갖고 있으면, 대시보드 레벨 필터를 하나 추가해 **모든 차트에 동시에 적용**되게 할 수 있음(우측 상단 `+ Add/Edit Filters`).
4. `Save`로 저장, `Draft`/`Published` 상태 전환 가능(Published가 완성본).

## 3장. 우리 Gold 테이블 8개 — 어떤 차트가 어울리는지 한눈에

(각 항목의 자세한 근거는 `04/이론.md` 참고)

| 테이블 | 추천 차트 | 이유 |
|---|---|---|
| `event_funnel` | Funnel Chart (또는 정렬된 Bar) | view→cart→purchase처럼 단계가 줄어드는 흐름을 보여주는 데 특화된 차트 |
| `category_revenue` | Bar Chart (Top N, 내림차순 정렬) | 카테고리(범주형) 간 매출 비교 — 항목이 많으면 상위 N개만 |
| `brand_revenue` | Bar Chart (Top N, 내림차순 정렬) | 위와 동일한 이유 |
| `daily_events` | Line Chart (날짜별, event_type으로 색상 구분) | 시간 흐름에 따른 추이 |
| `daily_purchase` | Line Chart 또는 Area Chart | 시간 흐름 + 값의 누적/크기감을 같이 보고 싶으면 Area |
| `price_stats` / `purchase_price_stats` | Table (또는 Big Number 여러 개) | summary(count/mean/stddev/min/max) 자체가 이미 요약 통계라 별도 차트보다 표로 그대로 보여주는 게 명확 |
| `price_percentiles` | Bar Chart (p25/median/p75/p95를 항목으로) | 분포의 구간별 값을 막대 4개로 비교 |
