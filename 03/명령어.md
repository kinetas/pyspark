# Airflow/오케스트레이션 명령어 정리

`02/명령어.md`(docker/kubectl 공통 명령)에 이어서, **Airflow 도입 이후 새로 쓴 명령어**만 정리. `docker`/`kubectl` 기본 사용법은 중복이라 생략하고 여기서는 03 폴더 특유의 것만 다룬다.

- 🔵 = 이 저장소 작업 중 실제로 사용함
- ⚪ = 아직 안 썼지만 알아두면 좋음

---

## 1. Docker Compose (03 전용)

| 명령어 | 설명 | 비고 |
|---|---|---|
| 🔵 `cd 03 && docker compose up -d` | Airflow 스택(kubeconfig-prep → airflow-init → airflow) 기동 | 02가 먼저 떠 있어야 함(네트워크/볼륨을 `external: true`로 참조). `-d` 없이 쓰면 세 컨테이너 로그가 한 터미널에 계속 출력됨 |
| 🔵 `docker compose logs -f airflow-init` | `airflow-init` 컨테이너 로그 확인 | DB 마이그레이션/계정 생성이 실패했을 때 원인 파악용. `Exited (0)`이면 정상 종료, `Exited (1)` 등이면 로그부터 확인 |
| 🔵 `docker compose logs -f airflow` | `airflow-standalone` 로그(웹서버+스케줄러+트리거러 통합) | DAG import 에러, 스케줄러가 태스크를 안 집어가는 문제 등 진단 시작점 |
| ⚪ `docker compose down` | 03 스택만 정리(02는 안 건드림) | Airflow 쪽 상태(sqlite DB, 계정)만 초기화됨. k3s/MinIO는 영향 없음 |

## 2. Airflow CLI (컨테이너 안에서 실행)

| 명령어 | 설명 | 비고 |
|---|---|---|
| 🔵 `docker exec -it airflow-standalone airflow dags list-import-errors` | DAG 파일(`.py`)에 파이썬 문법/임포트 에러가 있는지 확인 | **가장 먼저 확인해야 할 명령**. DAG 파일에 에러가 있으면 웹 UI 목록에 아예 안 뜨고(에러 메시지도 안 보임), 이 명령으로만 원인이 나옴 |
| 🔵 `docker exec -it airflow-standalone airflow dags list` | 스케줄러가 인식한 DAG 목록 확인 | `medallion_pipeline`이 안 보이면 위 명령으로 import 에러부터 확인 |
| ⚪ `docker exec -it airflow-standalone airflow dags trigger medallion_pipeline` | 웹 UI ▶ 버튼과 동일한 동작을 CLI로 | `--conf '{"kaggle_file": "2019-Nov.csv"}'`로 params 오버라이드 가능 |
| ⚪ `docker exec -it airflow-standalone airflow dags unpause medallion_pipeline` / `pause` | DAG를 스케줄 대상으로 켜기/끄기 | 웹 UI 왼쪽 토글과 동일. `schedule=None`이라 지금은 unpause 안 해도 수동 트리거는 되지만, 자동 스케줄(`@daily` 등)로 바꾸면 unpause가 필수 |
| ⚪ `docker exec -it airflow-standalone airflow tasks list medallion_pipeline` | DAG 안의 태스크 목록과 의존성 확인 | 코드를 안 열어봐도 태스크 구조 확인 가능 |
| ⚪ `docker exec -it airflow-standalone airflow tasks test medallion_pipeline bronze_to_parquet 2026-08-04` | 특정 태스크 하나만 DB에 기록 안 남기고 즉시 실행(디버깅용) | 실제 운영 실행과 별개로 로직만 빠르게 확인하고 싶을 때. 우리처럼 태스크가 K8s 팟을 새로 만드는 경우엔 결국 똑같이 팟이 뜸 |

## 3. K8s — Airflow가 만든 팟 확인

| 명령어 | 설명 | 비고 |
|---|---|---|
| 🔵 `docker exec -it k8s-master-node kubectl get pods -n default` | 지금 떠 있는/끝난 팟 전체 확인 | 이름 패턴으로 어느 태스크의 팟인지 구분: `ingest-kaggle-raw-*`, `bronze-parquet-job-*`(제출자) / `bronze-parquet-job-*-driver`(실제 driver), `silver-refine-job-*`, `gold-stats-job-*` |
| 🔵 `docker exec -it k8s-master-node kubectl logs <드라이버 팟 이름>` | Spark 태스크의 실제 실행 로그 | Airflow 태스크 로그(`get_logs=True`)에도 같은 내용이 나오지만, 팟이 삭제되기 전(`is_delete_operator_pod=True`라 태스크 끝나면 금방 지워짐)에 직접 보고 싶을 때 |
| ⚪ `docker exec -it k8s-master-node kubectl get pods -n default -l spark-role=driver` | 라벨로 현재 실행 중인 driver 팟만 필터링 | 여러 태스크가 겹쳐 돌 때 이름을 일일이 안 찾고 라벨로 좁힐 때 |

## 4. code-bucket 업로드 (boto3)

| 명령어 | 설명 | 비고 |
|---|---|---|
| 🔵 `pip install boto3` | MinIO(S3 호환)에 파이썬으로 접속하기 위한 SDK 설치(최초 1회) | AWS 공식 오픈소스 라이브러리, 무료. `mc`(MinIO 클라이언트)나 `aws cli`가 없는 환경에서 이걸로 대체 |
| 🔵 `python 03/upload_to_bucket.py` | `02/실습코드/01/*.py`, `03/ingest/ingest.py`를 code-bucket에 재업로드 | **코드를 고쳤다면 반드시 이 명령까지 실행해야 반영됨** — 로컬 파일만 고치고 이 단계를 빠뜨리면 8/4에 겪은 "옛날 코드가 계속 실행되는" 버그가 재발함(`03/시행착오_0803-0804.md` 참고) |
